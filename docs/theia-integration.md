# Eclipse Theia workbench beta

This directory adds an **optional** Eclipse Theia editor surface for the
SignalDesk learning workspace. It is not a replacement for the AIWEX workflow:
the platform continues to own onboarding, scenario checks, commits, pull
requests, review, merge gates, feedback, and the private event ledger.

The feature is disabled by default. A learner can always return to the built-in
workspace, so a missing or unhealthy Theia service cannot block the scenario.

## Boundary and data flow

```text
AIWEX browser
  -> authenticated session route -> short-lived signed Theia token
  -> postMessage (never a URL parameter) -> isolated Theia iframe
  -> allow-listed file revision route -> AIWEX event ledger
  -> normal AIWEX checks / commit / PR workflow
```

The bridge only receives the curated SignalDesk files. It can write one of
those existing files, up to 100 KB, through
`POST /api/simulation/ide/revisions`. The route checks the iframe origin, the
HMAC-signed session, onboarding access, file allow-list, and the last saved
revision before it appends a normal `workspace_revision_saved` event.

The workbench has no AIWEX credentials, database credential, native terminal,
process extension, host filesystem mount, or arbitrary extension installation.

## Local developer setup

The Theia project is intentionally separate from the Next.js package:

```powershell
corepack yarn --cwd theia install
corepack yarn --cwd theia build
corepack yarn --cwd theia start
```

For a local experiment only, set these server-side values in `.env.local` and
restart the Next.js server:

```env
THEIA_ENABLED=true
THEIA_WORKBENCH_URL_TEMPLATE=http://localhost:3001/
THEIA_SESSION_SECRET=replace-with-a-32-character-or-longer-random-secret
THEIA_SESSION_TTL_SECONDS=300
```

Do not set `THEIA_ENABLED=true` on a shared deployment merely because the
browser application builds. The iframe must be hosted separately and its
deployment must satisfy the isolation rules below.

## Production topology

Use a trusted workbench orchestrator or reverse proxy to send each private run
to a separate short-lived Theia container or pod. Configure a route such as
`https://theia.example/learner/{runId}/`; the `{runId}` value is substituted
server-side after the learner is authenticated. The template is required to
contain `{runId}` in production. Keep a stable Theia **origin** so the API can
enforce CORS; put the per-run value in the path, not the hostname.

Each instance needs an ephemeral writable `/workspace` only. Run it as a
non-root user with a read-only base image, no host mounts, no Docker socket, no
cloud credentials, no inbound access other than the trusted proxy, resource
limits, idle expiry, and deletion when the signed session expires. Do not add a
terminal or arbitrary plug-in installation without a separate threat model.

The application uses a five-minute token by default (maximum ten minutes). The
token is posted to the iframe only after it declares readiness. It is not
stored in local storage or sent as a query parameter. Deploy strict TLS,
`frame-ancestors`/CSP rules that permit only AIWEX to embed the workbench, and
origin-locked CORS for the revision route.

## Verification and release gate

Before enabling the flag for any learner:

1. Commit a `yarn.lock` generated by the successful install and run
   `corepack yarn --cwd theia build` in CI.
2. Exercise a signed-in user through onboarding, Theia editing and saving,
   normal scenario checks, commit, PR, review, and merge.
3. Test rejected cases: unauthenticated session request, wrong run ID, expired
   token, wrong origin, non-allow-listed path, stale revision, and a learner
   who has not completed onboarding.
4. Confirm containers cannot reach the host filesystem, shell, Docker socket,
   production services, or another learner's workspace.
5. Add monitoring for workbench launch failures, rejected saves, instance
   expiry, memory/CPU limits, and session cleanup.

## Rollback

Set `THEIA_ENABLED=false` and restart the Next.js service. Existing learner
data remains in the same event ledger, and learners immediately use the
built-in workspace. This does not need a data migration or a deletion of saved
scenario revisions.
