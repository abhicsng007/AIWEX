# Three-Minute Devpost Demo Script

Target length: **2 minutes 35 seconds to 2 minutes 50 seconds**. Record with clear spoken audio. Use your real deployment or local demo route, not a slide-only video.

## Before recording

1. Prepare a browser window at /demo?onboarding=1.
2. Use a browser profile without unrelated tabs, notifications, or personal information.
3. Increase zoom only enough for labels to remain readable.
4. Record system audio or a microphone narration. Do not use music you do not have permission to use.
5. Keep the cursor purposeful; avoid long typing clips and loading screens.

## Shot list and narration

| Time | Show | Say |
| --- | --- | --- |
| 0:00–0:18 | Landing/onboarding screen | “New developers can write code, but a first software job also expects stand-ups, review, trade-offs, and evidence of how work was done. AIWEX is a safe place to practise that complete workflow.” |
| 0:18–0:40 | Finish onboarding; enter the project | “This is a private scenario for a product team responding to a usage-alerts issue. Instead of a generic course, the learner has a concrete task, teammates, time pressure, and a visible trail of decisions.” |
| 0:40–1:04 | Post a stand-up and send a contextual teammate message | “The learner starts by communicating intent and risk. These are not disconnected screens: the app records actions as evidence, and missing or weak work creates follow-up rather than silently passing.” |
| 1:04–1:31 | Open workspace; make/save intended change; run scenario checks; record commit | “Next, the learner works in the guarded workspace, verifies the scenario, and records the commit. The workflow is server-validated and event-backed, so a browser button alone cannot establish progress.” |
| 1:31–1:59 | Open PR; respond to review; show approval and merge rationale | “The pull request makes review a real part of the exercise. The learner has to address feedback and explain why the merge is safe. This rehearses the reasoning and communication that most coding challenges leave out.” |
| 1:59–2:22 | Complete issue; open task report or final report/history | “Every task generates an evidence report: what was done, what was skipped, and what a recruiter or mentor can actually inspect. Across the project, those reports become a credible narrative of practice.” |
| 2:22–2:43 | Return to collaboration map or reports | “AIWEX helps candidates who do not yet have workplace experience demonstrate the habits behind reliable engineering — not just claim them on a résumé.” |
| 2:43–2:55 | Show README/Codex collaboration record briefly | “I built AIWEX with Codex and GPT-5.6 as development collaborators for product, engineering, testing, and documentation. Optional runtime teammate responses use the configured OpenRouter model, with a deterministic fallback so the experience remains testable.” |
| 2:55–3:00 | Logo or final report | “AIWEX: practise the work around the code before your first real team does.” |

## Capture checklist

- [ ] Video is public on YouTube.
- [ ] Runtime is under three minutes.
- [ ] Spoken audio is understandable.
- [ ] The video clearly shows the working product, not only source code or mockups.
- [ ] The video explains both what AIWEX does and how Codex/GPT-5.6 contributed.
- [ ] The video contains no unlicensed music, private data, or accidental secrets.
- [ ] The Devpost page uses the final public YouTube link.
